# Onboarding — Tickets

Builds on [00-fundament](../00-fundament/tickets.md) and
[02-plan-datenmodell](../02-plan-datenmodell/tickets.md). See
[spec.md](spec.md) for the goal and acceptance criteria.

### C1 — Chat UI scaffold
- The `/onboarding` route (auth-gated — redirect to `/login` if signed
  out): one continuous chat screen, no separate intro screen, using the
  Vercel AI SDK's `useChat` (see
  [ADR-0003](../../decisions/0003-chat-layer-vercel-ai-sdk.md)), still
  without a real Anthropic integration (mock responses); UI per
  [spec.md](spec.md) ("Design") and
  [docs/design-system.md](../../design-system.md)
- A record control for sending a voice memo instead of typing (UI only in
  this ticket — wired to real transcription in C2)
- **Acceptance:** messages are held and displayed via `useChat` state

### C2 — Claude integration + onboarding prompt
- An API route under `app/api/chat/` that calls Claude
  (`"anthropic/claude-sonnet-5"`) via the Vercel AI SDK (`streamText`),
  routed through Vercel AI Gateway rather than a direct `@ai-sdk/anthropic`
  provider (see [ADR-0006](../../decisions/0006-vercel-ai-gateway.md)),
  with a system prompt (coaching logic + training principles, reduced
  Phase 1/2/4/5 scope per [spec.md](spec.md) "Flow") — expanded per
  [ADR-0008](../../decisions/0008-full-horizon-deterministic-plan-generation.md)
  to also ask for preferred long-run day, schedule regularity, gym/
  strength access, and age/height/weight, and to reject/clamp a target
  date more than 12 months out (Spec 3, AC)
- A `proposePlan` tool defined alongside that same `streamText` call
  (not a separate `generateObject` step) with a Zod schema for the
  structured plan proposal (JSON per Spec 2) — the model decides on its
  own when to call it; its `execute` calls the progression algorithm
  (ticket C4) to compute the full-horizon structure, then Claude fills in
  the free-text phase/session prose within that structure (ADR-0008) —
  rendered client-side as the plan card (see "Design" in spec.md)
- A separate `app/api/chat/transcribe/` route that mints a short-lived
  Vercel AI Gateway client secret (`gateway.experimental_transcription.getToken`);
  the browser uses it to stream mic audio to `google/gemini-3.5-transcribe-live`
  live via `experimental_streamTranscribe` (see
  [ADR-0007](../../decisions/0007-vercel-ai-gateway-transcription.md)), and
  the resulting transcript is sent as a normal chat message
- **Acceptance:** the chat can ask for the target inputs (by text or
  voice) and return a plan proposal as structured data covering the full
  horizon (Spec 3, AC 1+2+voice AC+12-month-cap AC)

### C3 — Plan confirmation → DB
- Until this ticket ships, "Confirm plan" only flips local chat state —
  it must not claim to have saved anything (see [spec.md](spec.md)
  "Design")
- On confirmation in chat: the plan proposal is persisted to `Plan`/
  `Milestone`/`TrainingWeek`/`PlannedSession` for the full horizon (Spec 2
  AC, as revised by ADR-0008)
- **Acceptance:** after confirmation, the plan is queryable in the DB
  (Spec 3, AC 3)

### C4 — Deterministic progression algorithm
- A new module (exact location TBD at implementation time) that encodes
  the research's progression rules —
  `docs/research/progression-und-verletzungspraevention.md`'s 3:1
  step-loading with a 10–40% deload, the 6-month mileage progression
  table, and the RUNSAFE single-session spike-rule ceiling — and, given a
  `Plan`'s intake fields (goal, start/target date, training history, long
  run day, schedule regularity, gym access), computes phase placement,
  weekly volume, deload-week placement, and day-by-day session structure
  (type/duration/distance/pace/day-of-week) for the whole horizon (capped
  at 12 months, see ADR-0008)
- Used by both the `proposePlan` tool (C2) and a full replan (Spec 5,
  ticket E4) — the same algorithm, different inputs (fresh intake vs.
  updated progress/completed volume)
- Out of scope for this ticket: a taper for the "race" phase and any
  age/BMI-based rule (both explicitly deferred, ADR-0008)
- **Acceptance:** given a fixed set of intake inputs, the algorithm
  deterministically produces the same full-horizon week/session
  structure (no LLM call involved in computing the numbers)

### C5 — Plan card: full week switcher + workout legend
- Extend `plan-card.tsx` to navigate any week of the full plan (not just
  week 1), e.g. via a week switcher/accordion over the phase bar (Spec 3
  "Design")
- Render each session's `description` (currently generated by C2/C4 but
  discarded) and add a small static one-line-per-session-type legend
  (tooltip or inline) — see Spec 3 "Explaining workouts"
- **Acceptance:** any week in the full horizon can be viewed with its
  day-by-day sessions and descriptions; hovering/tapping a session type
  shows its one-line definition
